## Storage scan-open diagnostic fix — CODE stage complete

**Status: compiled and host-tested. NOT uploaded, NOT hardware validated,
NOT committed.** No serial port was opened, no board was touched, Experiment 3
was not reset, cleared or read. Every failure in this work is staged in a
pytest temporary directory.

### What changed — 4 files, +296/-17

- `Arduino/solar-logger/storage.h` — `AutoLogScan` gains `openFailed`.
- `Arduino/solar-logger/storage.cpp` — a failed read-open sets `openFailed` and
  `readError`; `autoStorageScanAndRepair()` reports the tail UNREAD and the
  counts UNKNOWN instead of falling through to "Log tail is intact: ALL OK".
- `Arduino/solar-logger/solar-logger.ino` — `printStorageInfo()` prints
  `Tail status: UNREADABLE`, prints no figure it never measured, and returns
  false so the command answers `CMD_RESULT,...,ERROR` (D-041) rather than `OK`.
- `tests/test_characterization_storage_recovery.py` — 7 tests plus one harness
  staging control that fails read-opens of the log and leaves the file alone.

`readError` is what carries the case into the existing refusals; `openFailed`
carries what it cannot, which is that a short read has real partial counts and
a failed open has none.

### SECOND DEFECT FOUND AND FIXED — worth your attention

Driven directly against an unopened log, `autoStorageTruncateToValid()` printed
"Rewriting the log to its valid prefix: 0 of 0 bytes" and proceeded. Only its
own source open failing for the same reason stopped it. A fault that cleared in
between would have copied keepBytes — zero — into the temp file, removed the
log and renamed the empty file over it, destroying every record. Not reachable
through `autoStorageScanAndRepair()`, which is exactly the case D-058 made for
keeping that refusal compiled in the function. `readError` now reaches it.

### FOUND, NOT FIXED — reported rather than absorbed, per the kickoff

`autoStorageRecover()` reseeds `rtcAutoRunChargeUAh`/`rtcAutoRunEnergyUWh` from
a scan that read nothing, so the RTC running totals silently restart at zero.
Same on the pre-existing short-read path. Changing it alters deployed
characterized accounting on both, so it is in BACKLOG as its own stage.
Two smaller, unchanged: the scan's error line prints before the "Scanning
durable log..." banner; `dumpStorage()` returns true after breaking on a short
read mid-dump.
